# 第 12 轮决定记录（2026-10-25）：幂级数与解的公式

> 第 12 轮的交付物（代号 AA；提交前缀 `[AA]`）。轮次对照表：[ROUNDS.md](ROUNDS.md)。

站长的要求（原话）：「现在课上出了 power series，我这个工具是否可以计算？不能的话把这个功能加上，然后加一个功能就是写出具体这个 power series 是怎么可以拆分的。还有普通的 1，2 阶也是，出一个可以拆分方程，然后学生可以自己拖动来看改变数字会对这个方程有什么影响。」

## 1. 理解与范围

| 要求 | 理解 | 做到的 |
|---|---|---|
| 工具能不能算 power series | 开工前**不能**：内核只有数值积分、平衡点、类型识别，代码里没有任何级数 | 新增精确计算的幂级数解 |
| 写出 power series「怎么拆分」 | 课本的推导步骤：设 Σ aₙ tⁿ、逐项求导、代入、平移指标、合并同次幂、递推公式、系数、把级数按 a₀、a₁ 拆成两个基本解 | 全部步骤，中英两套，精确分数 |
| 普通 1、2 阶也「出一个可以拆分方程」 | 常系数线性方程拆成齐次解 + 特解（特征方程、根、待定系数、共振、由初值定常数） | 「解的公式」，一阶二阶都有 |
| 学生拖动看数字的影响 | 已有的参数滑块驱动新面板；新面板自己的数字（展开点、项数、初值）也给滑块 | 实时重算；7 个新预设带好滑块 |

**没有做**（记入 open-questions）：系数不是多项式的级数（例如 sin(t)·x，要级数乘法）、变系数一阶的积分因子公式、非线性方程的泰勒系数、Frobenius 第二解里的对数项、平面线性系统的特征向量拆分。

## 2. 新代码放在 lib/series，不动冻结的内核

- 内核冻结（第 6 轮）禁止在 `lib/core` 里加新的数值机制。级数推导是站长明确要的新功能，但它是**精确有理数运算**，不是数值机制；为了让冻结规则保持字面成立，新模块放在 `lib/series/`，和 `lib/core`、`lib/render` 一样纯（加进 `lib/architecture.test.ts` 的 `PURE_DIRS`），只从 `lib/core` 读（解析白名单、二阶化简、积分器），`lib/core` 一个字没改。
- 精确：BigInt 有理数和高斯有理数（`rational.ts`）。tsconfig 目标是 ES2017，不能写 `1n` 字面量，全部用 `BigInt(...)`。
- 小数按**它写出来的样子**读成分数：`fromNumber` 取 double 的最短往返十进制串（`String(v)`），所以 0.1 = 1/10、滑块的 0.37 = 37/100；判别式 b² − 4k 在 b = 4、k = 4 时**恰好**为 0（临界阻尼），不会被二进制误差判成复根。π、e、函数值（sqrt(2)、cos(1)）按 16 位小数进入，并标记 `approximate`，推导下面加一句说明。

## 3. 读方程：精确的线性形式

`linear-form.ts` 把已经通过白名单的 mathjs AST 读成 `(u₀·U + u₁·U' + u₂·U'' + free) / den`，系数是拟多项式（多项式 × e^(λt)，λ 为高斯有理数）。支持加减乘、除以多项式或单个指数、整数次幂、一次自变量的 exp / sin / cos / sinh / cosh；其余一律拒绝并给出原因和片段（非线性、不支持的函数、非整数次幂、分段、除以非多项式、除以零、非有限、太大）。**不采样、不求值**：没有结论依赖采样运气。分母与所有分子的公因式约掉（t·x/t 就是 x）。

- 一阶：`dy/dt = g` 读成 D·y' − A·y = B（经 "ty" 白名单，x 照旧被拒）。
- 二阶：先跑 `reduceSecondOrder` 的全部检查，画面因**语法**拒绝的方程这里用同一句话拒绝。它的**数值**拒绝（`NUMERICAL_REDUCTION_CODES`：x'' 的系数在采样点为零、采样点上不是 x'' 的仿射函数、采样点上无定义、内部复核失败）在这里不算拒绝，由精确读法自己判断，不靠采样。t·x'' + x' + t·x = 0 的 x'' 系数在 t = 0 处为零，画面画不了，但这正是 Frobenius 的题目。评审还发现 (t² − 2)x'' + x = 0 被画面的采样复核拒绝，而它在 t₀ = 0 是常点（a₂ = a₀/4，半径 √2）；最初只放行「系数为零」一种，这类方程就被错拒了。
- **公因式**：所有系数和右端共有的多项式因式会约掉，推导里说一句（「每一项都有公因式 t，已约去；它的零点不是奇点」）。t·x'' + t·x = t² 就是 x'' + x = t，t = 0 是常点。评审发现原来把可约的公因式当成了奇点。
- `round()` 按 mathjs 的规则读（一半时远离零：round(−2.5) = −3），和画面积分的是同一个方程；原来用了 Math.round（−2）。第三轮起单参数的 round 在 2⁵³ 以下直接调用 mathjs.round（它会把差一个 ulp 的 2.4999999999999996 当成 2.5）；小数位数不合法时有自己的句子。
- 首项系数是 c·e^(λt)（永远不为零）时，整个方程先除以 e^(λt)，推导里说一句：eᵗx'' + eᵗx = 0 就是 x'' + x = 0。x'' 的系数恒为 0（参数滑到 0）时，句子说「这不是二阶方程」，不再说「不是线性的」。
- 「近似」分两种理由，各有自己的说明：π、e、函数值（16 位小数），以及输入的数位数超过 double（或超出范围，1e-400 读成 0）。拒绝的句子里给出**学生写的片段**（exp(800)·y 里的 exp(800)），不是算出来的值。17 位及以上有效数字的小数超出 double 的精度，也标记为近似。
- 符号：只有**负常数**首项系数会被翻号（x = x'' 读成 x'' − x = 0）；学生写的 (1 − t²)x'' 保持原样，不会变成 (t² − 1)x''。

## 4. 幂级数

- 每一项 c·sᵐ·u^(j)（s = t − t₀）平移后是 Σ_{n≥m} c·(n+δ)_j·a_{n+δ}·sⁿ，δ = j − m；合并得 Σ_δ Q_δ(n) a_{n+δ} = gₙ。常点（P_r(t₀) ≠ 0）时 δ = r 只来自 (j = r, m = 0)，Q_r(n) = P_r(t₀)(n+r)…(n+1) 永不为零，就是递推公式。
- 推导的显示和课本一致：各和式起点不同时，前几个 n 单独写（「n = 0：2a₂ + 6a₀ = 0，所以 a₂ = −3a₀」），然后 n ≥ n₀ 的一般式，再解出递推。分子分母按有理根分解显示：(n − 2)(n + 3)aₙ / ((n + 1)(n + 2))。
- 系数是 (a₀, a₁, 1) 上的向量，所以 u = a₀u₁ + a₁u₂ + u_p 是**精确**的拆分，a₀ = u(t₀)、a₁ = u'(t₀)。
- **「是多项式」只在证明后才说**：在递推齐次的区域里出现连续 r − δ_min 个零系数，之后全部为零（窗口论证）。Legendre l = 2 的 x₁ = 1 − 3t²、Hermite m = 2 的 1 − 2t² 都是这样被证明的；没有证明就写「+ …」。
- 收敛半径报告的是**定理保证的下界**：t₀ 到 P_r / gcd(P_r, P₀, …, G) 最近复零点的距离；复根对的距离平方是精确有理数（(1 + t²)x'' + x = 0 在 t₀ = 1 处得 √2），以 t₀ 为中心的实无理根对也是。措辞永远是「至少」。
- **找根**：线性、二次因式精确求根；更高次的因式先按有理根定理筛候选再精确验证；剩下的用 Durand–Kerner（先按 Fujiwara 界缩放），每个根要通过后向稳定的残差检验才算数。评审用 Wilkinson 多项式、k = 10⁴ 的远近根混合等例子找出了 NaN 和错误的半径。检验不通过的根记为「未定位」，半径改用 Cauchy 型的无根圆半径（`rootFreeRadius`），它仍是保证成立的下界，句子会说「有些奇点无法精确定位，但都不在 ρ 以内」。
- **数值根的距离要被证明**（第二轮）：后向稳定只说明近似值是「附近某个多项式」的根，不限制病态多项式的根挪了多远。(t² + 10⁻¹⁶)((t − 10⁸)² + 3) 的真实最近奇点在 ±10⁻⁸i，却报出「至少在 |t| < 1.374·10⁻⁷ 上收敛」，宽了 13.7 倍；10⁴⁰⁰t³ − 2 的常数项在 double 里变成 0，报出的半径是真值的 10¹¹⁸ 倍。现在每个数值根带一个**被证明的**包含半径：首一多项式 p 和互不相同的近似值 z_i，W_i = p(z_i)/∏_{j≠i}(z_i − z_j)，p 的每个根都落在某个圆 |z − z_i| ≤ n|W_i| 里（Lagrange 插值：p(z) = ∏(z − z_j)(1 + Σ W_i/(z − z_i))）。W_i 用 double 的**精确二进制值**在高斯整数里算，只有最后取模长时舍入，再放大 10⁻¹²。证明出的距离与估计值相差不到 10⁻⁹（`CERTIFIED_FRACTION`）时照常报告；否则报告证明出的下界与无根圆半径中较大的那个（`lowerBound`）。无根圆半径改用系数的精确对数计算，10⁻⁴⁰⁰ 的系数也算得出来。
- **距离用对数算，不会溢出**（第三轮）：所有精确距离都由精确有理数的对数得出，按对数比较。原来超出 double 范围的距离（10⁴⁰⁰ 处的奇点）在比较时被跳过，句子说「方程没有奇点，对所有 t 收敛」。实根对不在展开点正中时，近的那个根的距离用 |o² − w²|/(|o| + w) 计算，分子是精确有理数：t₀ = 1.4142135623730951 到 √2 是 5.1·10⁻¹⁷，不是 0，也不会说「无法精确定位」。只把**近的那个**根写成最近奇点（「t = √2」，不是「±√2」）。
- **保证的区间一律向下舍入**：「至少在 |t − t₀| < ρ 上收敛」里的 ρ 是保证，打印时向下舍入（√1.49000000001 打成 1.22065，不是 1.22066；10^0.15 打成 1.412）。估计值「距离 ≈ 1.413」照常四舍五入。数值共轭根合并成「t ≈ −0.7649 ± 0.3525i」，不再出现「t = ≈ …」。
- **代价**：展开点的 Taylor 平移太大（t₀ 的十六进制位数 × 次数超过上限，例如 t₀ = 10⁻³⁰⁰）时，直接说「这个展开算起来太费时」（`SeriesTooExpensive`），不再先卡住再等超时。找根、平移、gcd 都接 checkpoint。
- 奇点：判断正则 / 非正则，给出指标方程。**Frobenius**：齐次方程、指标根为有理数时展开；大根总能展开；小根在两根之差不是整数时、或差为整数 N 但递推在 N 处恰好留出自由系数时展开（t²x'' + tx' − x = 0 的 x₂ = t⁻¹、Bessel ½ 阶的 cos t/√t）；两根相等或递推在 N 处失败时，如实说「第二个解含 u₁ ln|t − t₀| 项，本工具不展开」。收敛到**最近的另一个**奇点。
- 整数差 N 的判断**在 n = N 处做**，和显示几项无关。评审发现 t²x'' + tx' + (t² − 225)x = 0（Bessel 15 阶，N = 30）只显示 8 项时被判错。N 超过 `FROBENIUS_GAP_CAP`（200）或系数位数先到上限时，如实说「要算到 n = N 才能确定，超出了这里能算的范围」（`undecided`），不猜。

## 5. 解的公式（常系数）

- 特征多项式的判别式是精确有理数，三种情况精确判定。根为无理时保留 √（例如 −1/4 ± (3√7/4)i），并附小数。
- 待定系数法对右端每个指数 μ 精确求解（高斯有理数上的三角方程组）；μ 是特征根时乘 t^s（共振），推导里明确说出来。x'' + x = cos t 得 (1/2)t sin t。
- **齐次基底以 t₀ 为锚**：e^(r(t − t₀))、(t − t₀)e^(r(t − t₀))、e^(α(t − t₀))cos β(t − t₀)……推导里也这样写。评审发现原来的 e^(rt) 基底在 t₀ = 800 时常数溢出成 Infinity / NaN / 0，在 t₀ = 10 时 y' = −100y + 100 的常数是 e^1000 量级。现在常数和初值同一量级。
- 常数：t₀ = 0，或右端是多项式，且根允许时，给精确分数；否则给 6 位有效数字并注明「近似值」（原来 4 位，与核对用的未舍入常数差太多）。x_p(t₀) 本身超出浮点范围时（右端 eᵗ、t₀ = 800），拒绝并说明（`formulaOverflow`）。
- **近共振**：外力频率以 16 位小数代入（x'' + 2x = cos(√2 t)）时，χ(μ) 只剩舍入噪声，精确公式的系数在 10¹⁵ 左右，对学生毫无意义。输入是近似的，且 |χ(μ)| ≤ `NEAR_RESONANCE_FRACTION`（1e-12）× Σ|P_j||μ|^j 时，面板不给公式，说明「两个频率在舍入误差内相等；本来就该相等的话这是共振，本工具只能对有理数频率精确写出」。精确输入（x'' + 4x = cos 2t）照常判为共振；π² 对 cos(πt) 的对照例子照常给公式。
- **多个强迫项**：每一项有自己的待定系数字母和名字（x_p1、x_p2），最后一行叠加 x_p = x_p1 + x_p2。x'' + 4x = cos t + sin 2t 得 (1/3)cos t 与 −(1/4)t cos 2t。
- **稳态**：只有齐次解衰减、而且每个强迫指数的实部为 0（常数、多项式、无衰减的正弦）时，才说「长时间后 u ≈ u_p」。强迫项 e^(−2t) 比齐次解衰减得还快，说 u ≈ u_p 是错的；增长的 eᵗ 也不说。
- 阻尼说法只在 P₂ > 0、P₁ ≥ 0、P₀ > 0 时给，句子里不再引入 m、c、k（学生的参数正好叫 c、k、m 时会冲突）。
- **快模态与相消**（第二轮）：核对区间改为 |t − t₀| ≤ min(1, 8/|Re r|最大)（`CHECK_GROWTH`）。积分器的误差按 e^(|Re r||t − t₀|) 放大，y' = 40(y − t)、y(0) = 1/40 的精确解 y = t + 1/40 原来被判「未通过，请报告」，现在只在 |t| ≤ 0.2 上比较并通过。公式各项比解本身大 10⁸ 倍以上时（精确的近共振频率 cos(1.41421356237 t)，各项约 10¹¹ 并相消），浮点运算分辨不出差别，就不做数值比较，核对句说明原因（`CANCELLATION_LIMIT`），绝不说「未通过」。只比较到初值本身一个点的（平衡点 x ≡ 1、t₀ 处 0/0 的场）也不算比较。
- **第三轮对核对的修正**：
  - 解很小时（初值 10⁻⁷），参考积分的绝对容差跟着解的大小缩小，不再用固定的 10⁻¹²。原来正确的公式会被判「未通过」。
  - 相消的上限改为 10⁹（`CANCELLATION_LIMIT`）。实测比例 10⁹ 时比较误差仍只有容差的十分之一，原来的 10⁸ 太严。
  - 比例里的「解的大小」取自参考积分，不取相消的公式值本身。
  - 公式各项相消到画不准时，图改画数值解，并说明原因（`chartCancellation`）。
  - 近共振只在**那个指数本身**像是 double 舍入出来的（16 位以上，或不是有限小数）时拒绝。别处的 π 不会让一个精确输入的频率被拒。
  - 溢出的提示只在挪 t₀ 有用时才建议挪 t₀。
- **自检分两步**：先把 x_p **精确代入**方程，残差恰好为 0 才往下走，否则写「核对未通过，请报告」；再在 |t − t₀| ≤ 1（`CHECK_HALF_WIDTH`）上和内核积分器（rtol 1e-10、atol 1e-12）比较，偏差不超过解自身大小的 1e-6 才写通过，句子写明**实际比较到的范围**。评审发现两种错：初值压住增长模时（y' = y − sin t，y(0) = 1/2），积分器的误差被放大成 e²⁰ 倍，正确的公式被判成未通过；参考解提前停下时，句子仍然声称核对了整个范围。

- 二阶推导里没有任何 y，一阶推导里没有 x、没有 dy/dx（测试扫每一行，中英两种语言）。

## 7. 网页、预设、链接、Claude

- 面板只出现在一阶 dy/dt = g 与二阶模式（微分形式和平面系统不是「一个未知函数的一个方程」）。控件在左栏（三段按钮：关闭 / 幂级数 / 解的公式；展开点、最高次数、初值，各带滑块），结果在图下方（标题、图、编号步骤）。
- 图用解的图像同一套绘制（`drawTimeSeries`），只新增两个**可选**字段 `extras` / `bands`；网页其他地方和 widget 都不传，像素不变，**不升 widget 版本**。级数图在半径有限时取 t₀ ± 2.5ρ，阴影带是 |t − t₀| < ρ；否则取画面的 t 范围。
- 链接：`ser`（ps / sol）、`sn`、`sc`、`si`，只在一阶与二阶模式有效，其余模式报 `unusedInMode`。

## 8. 精确运算的代价上限（MCP 工具那一路实测出来的阻断问题）

- 现象：`(1+t)^10*x'' + x = 0` 在 t₀ = 0.123456789 处，系数每一次幂长约 90 位，60 个系数长到 5000 多位，每次运算都要对这么大的数做 gcd：`powerSeries` 7.6 s，推导再卡死；而且引擎不接 checkpoint，2 s 预算拦不住。公开端点和学生的浏览器都会挂住。
- 修法三条，都不改数学：① 只算「显示到的次数 + 20」个系数（20 留给多项式的证明窗口），最多 60；② 一个系数超过约 1200 位（1000 个十六进制位）就停在那里，算出来的仍然精确，推导下面说明停在哪一次；③ 引擎的每个循环接受调用方注入的 checkpoint（`lib` 里仍然没有时钟），网页给 1.5 s、工具给原有的 2 s 预算；网页上超时只显示「这个展开算起来太费时」，不会让页面出错，工具返回预算的 isError。
- 顺带修了一个真 bug：`isqrt` 原来从浮点估计出发，对超过 2⁵³ 的数估计可能**低于**真根，之后一次加 1 往上爬，永远爬不完（推导卡死的直接原因）。现在从 2^⌈bits/2⌉（一定不小于根）开始做 Newton，单调下降，O(log bits) 步；新测试用 (10¹⁴⁵ + 7)² 验证。
- 修后同一批输入：`powerSeries` 47–62 ms，度数 40 的系数在 t₀ = 0.5 处 0.7 s，推导 13–26 ms。
- 工具不画图，所以幂级数那一路不再做参考积分（`chart: false`）。核对句写明核对的范围（「对 −5 ≤ t ≤ 5」），因为工具没有「所画范围」。

## 9. 精确运算的代价（第二轮）

- **gcd 先做模素数检验**：把两个多项式模 2³¹ 以下最大的三个素数之一化简后做 Euclid；模 p 的 gcd 次数是 0 就**证明**了互素（Gauss 引理：Q 上的公因式化为本原整系数后，p 不整除首项系数，模 p 次数不变）。常见情况（分子与分母、多项式与它的导数）几乎都互素，原来 (t + π)¹⁶ 对 (t² + 1)⁸ 的精确余式序列要 1.3 秒，现在不走一步。不互素时仍用精确的首一余式序列。
- **解的公式也有位数上限**：待定系数超过 `MAX_COEFFICIENT_HEX_DIGITS` 就停，说「这个解的公式算起来太费时」。精确代入检验改为逐个指数做，每步接 checkpoint。原来 x'' + πx' + ex = t⁴⁰(cos πt + cos et) 在 MCP 上 21 秒（九个频率 148 秒）才返回，2 s 预算完全管不到。
- 精确数字太长有自己的理由和句子（`tooManyDigits`），不再借用「次数超过 40」。常数的整数次幂（2⁴¹、0.5⁶⁰）直接精确算。
