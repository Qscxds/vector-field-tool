# PQR 轮待决事项

1. **Codex 内核改动的授权**（P0）。`CLAUDE.md` 与 `docs/ENGINEERING-RECORD.md` 都写「2026-09-10 站长明确授权的窄例外：非自治零速度误停」。我无法核实这句话。改动本身不调任何数值阈值、只用既有静态规则 `mentionsTime`、修的是可推导的真错误（`x' = 0, y' = t` 从静止出发 y(1) 应为 1/2），所以我保留了它并原样提交为 `59365b7`。**请确认**：如果这不是你授权的，回滚 `lib/core/integrate.ts` 的那一段（`hasEquilibriumStop`）和对应测试即可，其余 Codex 改动与内核无关。

2. **`query_solution` mode second 的 `y0` 兜底**（P1）。新参数是 `xp0`；为了不让缓存了旧描述的会话直接报错，`y0` 在 second 模式仍被静默当作初速度读取（两者同时给且不同则拒绝）。如果你希望更严格（只认 `xp0`），删掉 `tools.ts` 里的那一行兜底即可。

3. **`t0` 在 system/second 模式的语义改变**（P1，R.1 提前）。以前 `t0` 是 `x0` 的别名；现在是起始时刻（默认 0）。旧对话里 Claude 若还按别名传 `t0` 而不传 `x0`，会得到一条可读的错误（"needs x0 … t0 is the start time"）。重新连接连接器后描述会更新。

4. **`trace_trajectory` 没有二阶/一阶模式**（P2 扫描）。学生说「画 x'' = −sin x 过 x(0) = 1, x'(0) = 0 的解」时，Claude 可能手工降阶再调 `trace_trajectory`，摘要就会说 y。本轮只在描述里堵：PLANAR SYSTEMS ONLY，方程一律走 `query_solution`（远目标即画整条曲线）。更彻底的做法是给 `trace_trajectory` 加 mode first/diff/second（复用 reduceSecondOrder 与二阶表头），留待下一轮。

5. **微分形式常数解的「稳定性」**（P2.3）。内核按 dy/dt = −M/N 的符号（t 增大方向）判定，数学上成立但这种形式本身无方向；我保留了判定并加了一句说明来源。如果你觉得对微分形式根本不该报稳定性，改 `analyze_first_order` 与两个外壳在 `spec.kind === "differential"` 时只列常数解、不列稳定性即可（内核不用动）。

6. **首页/帮助里「向量场」这个词用在一阶方程上**。工具名叫「向量场教学工具」，一阶方程的图严格说是斜率场；扫描把它列为「产品名，可接受」，我同意，没有改。

7. **Q.3 共振响应曲线未做**（Q）。振幅–频率曲线需要对每个驱动频率积分到稳态再量振幅，这是一套新的数值扫描，触及内核冻结，且「稳态」何时到达本身就要判据。本轮只提供时间序列视图（受迫、拍频、共振随 t 的增长都能看到）。要做的话建议下一轮单独立项，措辞按「未能否定」写。

8. **widget 没有时间序列视图**（Q）。MCP 工具返回的曲线不带 `times`（每点的时钟），加上会明显增大 structuredContent。网页壳的时间序列完整可用；Claude 里的 widget 仍只有相平面。要补的话：`trace_trajectory` / `query_solution` 的 legs 加 `times`（可抽稀）+ widget 加切换 + `WIDGET_VERSION` 升 `p-2`。

9. **「同时画 x'(t)」不进链接**（Q）。它是显示选项，默认关；分享链接打开时只画 x(t)。如需，加一个 `xp=1` 参数即可（`lib/url-state.ts` + 网页壳各一行）。

10. **时间序列的曲线只算到 t₀ ± 50**（Q）。与相平面同一规则，超出时图中空白并有说明。如果教学上常要看更长（例如拍频包络 2π/0.1 ≈ 63 的整周期），可以把 `CLICK_TSPAN` 调大（一个常数，两个视图同时变长），代价是每次重算更慢。

11. **CI 还没在 GitHub 上跑过**（R.2）。**已解决（S 段）**：第一次运行在 `npm test` 失败——两个平衡点测试在 GitHub 的 2 vCPU 机器上超过 vitest 默认 5 s 超时；`vitest.config.mts` 的 `testTimeout` 提到 20 s 后变绿（run 35028983127）。原文：工作流是本地写的，仓库没推；第一次 `git push` 后到 Actions 看它是否绿。可能的差异：Linux 上的构建（本机是 Windows），`npm ci` 对 lockfile 的严格校验。都不影响线上（Vercel 独立构建）。

12. **「计算中」只覆盖同步渲染阶段**（R.1）。平衡点搜索在渲染里，提示能盖住它；曲线追踪在 effect 里，一次改范围重追踪 20 条长曲线时仍可能卡一下而没有提示。内核没解冻，慢的地方本身没变快。

13. **「报告问题」会把当前完整链接放进公开的 issue**（R.3）。链接只含方程、范围、曲线起点，没有个人信息；但学生若把名字写进方程或链接，发出去就是公开的。帮助页写了「发不发由你」。

14. **widget 的上限提示依赖悬停**（R.1）。触屏没有悬停，满 20 条后点空白无反应也无提示（网页有常驻提示；widget 没有添加按钮，只能点画布）。要补的话给 widget 加一行常驻提示即可。

15. **每个提交的门禁**：R 段五个代码提交是按模块拆的，三个门禁在段末的最终状态上跑（tsc 0、954 通过、构建通过），中间提交只按依赖关系保证能编译（后一个提交只新增使用）。如果你要求逐提交验证，`git rebase -x "npm test" q-timeseries-done` 可以补跑。
