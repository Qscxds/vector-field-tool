## 2. T 段：符号参数

**内核只加了三个静态辅助，没有任何数值机械。** `parameterNameProblem`（`validateParams` 本来就在用的参数名规则，导出后网页与链接用的就是编译器自己的规则，不另写一份）、`freeSymbols`（parse.ts）、`freeSymbolsSecondOrder`（second-order.ts）。三者都只 parse 不求值，没有阈值。`freeSymbols` 对「当前解析不了的文本」返回 `null` 而不是 `[]`——`null` 不等于「没有参数」，学生打到一半（`k*`）时参数行保持不动，不会闪。

**自动发现的两条护栏（防止把漏写的乘号当成参数）：**
- 只由本模式变量字母组成的多字母名（一阶里的 `ty`、系统里的 `xy`、二阶里的 `tx`）**不算参数**，留给内核原有的「Did you mean t*y?」报错。否则 `sin(ty)` 会静默变成 `sin(1)`。
- 两个字母、其中一个是变量字母的名字（`ky`、`at`）**照样列出**（规则分不清 `ky` 和 `k2`、`Ta`），但待赋值的那一行会写明「ky 被当作一个参数；如果想写乘积，请写 k*y」。

**参数行的状态模型（`lib/params.ts`，纯函数，可测）：**
- `auto` 行跟着方程走：出现就加（值 1、高亮「待赋值」）、不再使用就移除；移除时值和滑块进 `memory`，名字再出现就原样恢复。这同时满足「参数区跟着增删」和「已有的值要保留」。敲 `alpha` 途中出现的 `a`、`al`、`alp` 是未赋值的待定行，移除时不进 memory，不留垃圾。
- `manual` 行（学生点「添加参数」加的）不会被自动移除，名字可编辑；auto 行的名字属于方程，只读。
- **删除仍在使用的参数被拒绝**（`removeParamRow` 返回 `refused`），那一行保留并提示「方程仍在使用 k」。不这样做的话自动发现会立刻以默认值 1 把它加回来，就是简报禁止的「静默恢复默认值」。
- 值是文本，`-`、`0.` 可以慢慢打；非法时**上一次的合法值继续生效**，并在该行写明「图上仍在用 k = 0.3」。不白屏，也不假装用了新值。
- 交给编译器的只有「合法且被方程使用」的行；一个参数都没有时传 `undefined`，无参数的页面编译结果与 T 轮之前逐字节相同（widget 的 systemKey、既有测试都不受影响）。

**参数值改变不是方程改变。** 它进 `retraceKey` 而不是 `systemKey`：固定的曲线保留并按新值重追（同一批初值点在新参数下的解），查询结果丢弃，预设选中状态取消（预设的说明是针对它自己那组值手推的，换了值就不成立）。

**链接（`p=k:0.8,L:2`）：** 先解 `p` 再解表达式，表达式带着参数一起过同一个白名单。名字用内核规则校验，值用既有的严格十进制 + ±1e6 界。非法条目**整条丢弃**并以 `p:名字` 报告（新增三个原因：`badParamName`、`reservedParamName`、`duplicateParam`），不会半读半丢。链接里方程用了 `k` 却没给值**不算错误**：页面照样打开，`k` 以待赋值状态列出。值用 `String(n)`（能精确读回的最短十进制），`:` 在链接里保持可读。

**T.4（摘要不说参数取值，是现存 bug）：** `withParams` / `paramsSentence` / `withSceneParams` + `sceneParams`。只列方程真正用到的名字（工具调用可能带多余的参数）；二阶场景从学生写的方程读名字（化简后的 g 可能把 `0*b*x'` 里的 `b` 化掉）。位置：一阶、二阶（降阶那一行）、`analyze_system`、`trace_trajectory` 接在方程后面；`sample_field` 和 `query_solution` 的平面模式单独一句「Parameter values: …」（前者方程写在括号里，后者表头已经有一个 with，接上去会成「… with k = 4 with (x(0), y(0)) = …」）。没有参数时逐字不变，绝无空的 with（有测试）。

**widget 改了，所以 `WIDGET_VERSION` = `t-1`。** widget 摘要现在带参数取值（简报 T.4 明确要求）。`scripts/smoke.mjs`、`server.test.ts` 跟着改；`lib/changelog.ts` 的条目带 `action`（删除连接器后重新添加）。顺手把 `server.ts` 注释里的「disconnected and reconnected」改成 remove and re-add。

**预设：** Logistic（k = 0.8, L = 2；范围改到 t∈[0,10]、y∈[−0.5,3] 才看得见 y = L）、**新增**牛顿冷却（k = 0.3, Ta = 20；y∈[0,40]）、阻尼振子（b = 0.25, w = 1）、受迫 / 拍频（F = 0.5, g = 1.2）、Lotka–Volterra（a = 1, b = 0.5, c = 0.75, d = 0.25）。LV 没用全 1：全 1 和自动发现的默认值一模一样，学生看不出这些是「设过的值」。选的这组使第二个平衡点落在 (c/d, a/b) = (3, 2)，两条预置轨线的范围用守恒量 H = d·x − c·ln x + b·y − a·ln y 手算过，都在框内。

**我自己写错又改掉的两条测试期望（都不是容差问题）：** ① 断言「自动发现的顺序 = 预设 params 的顺序」，但发现按出现顺序是 a, b, d, c——规则本来说的是「集合相等」，改成按集合比较；② 手写 logistic 预设链接时漏了预设自带的 `traj`。两处都是我推导时的疏漏，期望值改后仍然是按规则推出来的。

## 3. U 段：滑块

**实测耗时（node，本机）：** features 计算 logistic 6 ms、阻尼振子 12 ms、LV 21 ms、`x' = k x y, y' = x² − y` 约 1 s；采样场 0.3 ms；一条固定曲线 0.6–5 ms；二阶降阶 1–1.5 ms。

**拖动时的策略是自适应的，不是一刀切防抖（`lib/feature-schedule.ts`）。** 简报 U.2 要求贵的东西防抖 250 ms，U.3 又要求分类那一行「随滑块连续更新」，两条对便宜的方程是矛盾的。实测绝大多数课堂例子的 features 只要 6–21 ms，所以：上一次 features 计算 ≤ 25 ms → 每个滑块值都同步重算（分类连续更新，螺旋→结点看得清）；> 25 ms → 沿用既有的 250 ms 防抖，上一次结果留在屏幕上、变淡、浮出「Computing…」。不在拖动时一律不延迟。防抖本身是一个注入时钟的纯状态机（可测），hook 只管定时器。

**生产构建上发现并修掉的问题：** 页面第一次 features 计算是「冷」的（JIT 还没编译内核），比热的 12 ms 贵好几倍，超过 25 ms 预算后整个第一次拖动都被锁在防抖里——而防抖期间不会再测量，策略翻不回来，分类就不跟手了。修法：页面的前 3 次测量按 150 ms 的宽松预算判断。真正贵的方程（~1 s）两个预算都超，照样防抖。**这个问题只在生产构建里出现，dev 下看不到**，所以 U 段的性能结论必须以生产构建为准。

**没有做「拖动时降低网格密度」。** 采样场只要 0.3 ms，降密度省不出任何可感知的时间；生产构建实测每个滑块值中位 33.5 ms（≈30 次/秒），不算明显掉帧。按简报「如果掉帧明显才做」的条件，不做，并在此记下。

**滑块细节：** 默认范围 0..2|v|（负值镜像为 2v..0，0 处 −1..1），约 100 个「好看」的步长（1/2/5×10^k）；`snapToSlider` 贴到步长网格并去掉二进制噪声（链接里是 0.3 不是 0.30000000000000004）；最多 10000 步（否则一次拖动会灌爆内核）；只有**显示着的**滑块进链接（`sl=b:0:2:0.01`）；范围字段是文本，非法时上一次的合法范围继续驱动滑块并说明。值在范围外时不动值（输入框是事实），滑块停在近端。

**U.4 / 上一轮 open-questions #10：** 固定曲线的跨度改为跟随时间序列视图的 t 范围：每个方向 = max(50, 从 t₀ 到范围端点的距离)，上限 `MAX_TRACE_TSPAN` = 500。只对平面图生效；一阶图不变。相平面的曲线因此也可能更长（同一个解，跟得更久），查询面板用同一跨度。没碰内核：同一个积分器，积得更久。

## 4. V 段：相平面辅助线

**全部放在内核之外的 `lib/phase-aids.ts`，零新数值方法：** 零斜线复用 `lib/render/contours` 的 marching squares；特征向量是 2×2 闭式，取内核已经返回的 Jacobian；分界线用既有的 `integrateAdaptive`。

**符号变化不等于零点。** marching squares 只看符号翻转，`1/x` 过极点、`sign(x) − 0.5` 过跳变都会翻号却不为零。一条线段只有在它中点处的函数值 ≤ 所在格四个角点最大绝对值的 25% 时才保留（真正的零点处是 O(h²)，极点处远大于角点，跳变处与角点同量级）。这是内核之外新增的一个启发式常数（`NULLCLINE_RESIDUAL_FRACTION`），有推导测试（`1/x` 无零斜线、`tan x` 只留零点不留极点）。局限见 open-questions。

**特征方向由内核自己的分类决定，不在这里重新判定：** 鞍点和普通结点两条；**退化结点一条**（取重根 tr/2），ⓘ 里明说「这正是退化结点的定义特征」；星形结点每个方向都是，所以不画并说明；复特征值（螺旋、中心或弱螺旋）不画并说明；非双曲点不画（线性化什么都决定不了，它自己的 caveat 已经说了）。线段长度在**屏幕**上固定（画布短边的 11%），任何缩放下一样长。

**分界线的偏移量是相对的：** features 所用范围对角线的 1e-3（屏幕上约 1 像素），不是绝对数。不稳定流形正时间积分，稳定流形逆时间积分；终止框用固定曲线自己的远框（20×），所以分界线和一条固定曲线跑得一样远。只对鞍点画。

**不只靠色相：** 第一族零斜线实线、第二族虚线；稳定方向实线 + 箭头朝里，不稳定方向虚线 + 箭头朝外；分界线粗黑，稳定流形实线、不稳定流形虚线。图例在画布右上角，名字用学生自己的记号（规则 9）：系统 `x' = 0` / `y' = 0`；二阶 `x' = 0` / `x'' = 0`（没有 y）；一阶 `dy/dt = 0`；微分形式 `N = 0` / `M = 0`。

**开关：** 三个独立的复选框（「在图上显示」），默认全关，进链接 `aids=n,e,s`；一阶图只提供零斜线（`e`、`s` 写在一阶链接里会被报告为未使用）。时间序列视图下隐藏（值保留）。`Scene.aids` 只在开关打开时由 hook 填；**没有任何工具填它**，工具的 Scene 和摘要不变。

## 5. W 段：讲课模式

**纯展示层（`lib/lecture.ts`）：** 每一行「打印什么」由纯函数决定（`equilibriumLine`、`constantSolutionLine`、`constantSolutionTag`、`lectureNotices`、`lectureQueryShort`、`lectureCurveNote`），读 Scene 的条目、不改它。`lecture` 不在任何计算的依赖列表里，所以切换不重算，切回来所有数字立刻都在。工具层完全不知道这个词——有一条源码检查：`app/mcp/*`、`lib/scene.ts`、widget 页、`lib/core/*` 里不出现 “lecture”。

**隐藏什么、保留什么**照简报的表：隐藏特征值 / tr / det / 平衡点坐标 / 常数解的数值 / 偏差与阈值 / 范围行 / 扫描分辨率行 / 查询数值 / 最后一条轨线那行 / 二阶的解释句；保留分类名、图上的标记、「与可分离方程一致」、坐标轴与刻度、**方程 + 参数取值那一行**（那是这堂课正在讲的东西，不是干扰）。

**红线（都有测试）：**
- 「中心或弱螺旋（线性化无法区分）」逐字不变；非双曲点的名字本身带「线性化无法判定」。这两类 caveat 不需要短句，因为分类名已经说了。
- repeatedRoot / notFinite / domainEdge 三个 caveat 各有一个短句（`caveatShort`），接在分类名后面。临界阻尼 b = w 时讲课模式显示「退化结点 · 重根或近重根（数值上无法区分）」，没有为了好看压掉。
- 唯一性失效：平衡点 / 常数解那一行保留以「!」开头的短句，画布上常数解的标签保留「 !」，徽章照画。
- **收尾时自己查出来的一个缺口：** 讲课模式隐藏「最后一条轨线」那行时，把「这条曲线经过唯一性失效点，它只是无穷多条解中的一条」也一起藏掉了。已补：讲课模式下保留一条「!」短句 + ⓘ 全文（`lectureCurveNote`）。
- 搜索的警告（连续平衡点集、非双曲多点、超上限、整片区域）保留短句；其余提示（截断、奇点、下溢平台、扫描分辨率）折成一行「关于这次搜索的说明（n 条）」+ ⓘ，一条不丢。

**每一行仍有 ⓘ，第一项就是普通模式下完整的那一行**（坐标、分类、λ、tr、det），后面跟普通模式 ⓘ 里的全部内容。
