# 第 12 轮遗留问题（2026-10-25）

> 第 12 轮的交付物（代号 AA；提交前缀 `[AA]`）。轮次对照表：[ROUNDS.md](ROUNDS.md)。

`lib/core` 一个字没动，没有改过任何既有容差，没有 `it.fails()` 标记的新测试；widget 没有变（仍是 `z-1`）。下面按「课上最可能撞到」排序。

1. **系数不是多项式的幂级数还不能做。** 例如 x'' + sin(t)·x = 0、x'' + eᵗx = 0：课本会把 sin t 展开再做级数乘法（柯西乘积），系数不再是两三项的递推。面板现在说「系数要求是 t 的多项式」。要做：在 `lib/series` 里加截断幂级数乘法（t₀ = 0 时 sin、cos、exp 的泰勒系数都是有理数，仍然精确），推导步骤多一步「把 sin t 展开」。右端是 eᵗ、cos t 的级数（g_n 不再有限）同理。
2. **Frobenius 第二解的对数项没有展开**（两根相等，或相差整数且递推在 N 处失败，例如 Bessel 1 阶）。现在如实说「含 u₁ ln|t − t₀| 项，本工具不展开」。要展开需要 d/dr 法或降阶法，代数量明显更大。
3. **指标根是无理数或复数时**（例如 t²x'' + tx' − 2x = 0，r = ±√2）不展开 Frobenius 级数（系数会落在 Q(√2) 里，`rational.ts` 只有 Q 和 Q(i)）。
4. **变系数一阶线性方程没有「解的公式」**（dy/dt + p(t)y = q(t) 的积分因子要做符号积分）。现在这类方程只能用幂级数面板（p、q 是多项式时）。
5. **解的公式只覆盖常系数**；Euler 方程（t²x'' + a t x' + b x = 0）在 t > 0 上也有经典的公式解，目前只在 Frobenius 里出现（它恰好是 Frobenius 的特例）。
6. **级数图的纵轴用的是你输入的范围**（一阶是 y 的范围，二阶是 x 的范围），和解的图像一致；解很小（受迫振子的振幅 0.3）或很大时，曲线会显得扁或出界。可以改成按曲线自动取范围，但那样会和画面的范围对不上。请看一节课再定。
7. **级数图半径有限时取 t₀ ± 2.5ρ**，不跟随画面的 t 范围（否则 Legendre 在 [0, 20] 上 95% 的画面都是发散）。半径无穷时才用画面的 t 范围。
8. **系数显示上限**：分子分母合计超过 16 位的分数改显示 6 位有效数字的小数，推导下面有一句说明。Airy 显示到 t³⁰ 时会出现这种情况。
9. **π、e、函数值按 16 位小数代入**后做精确运算：分数是那个小数的精确结果，推导下面有说明；位数会长，常常触发第 8 条。
10. **微分形式 M dt + N dy = 0 和平面系统没有面板。** 平面线性系统的「特征值、特征向量拆分」是自然的下一步，但不在本轮要求里。
11. **展开点不是 0 时**，推导先把系数改写成 (t − t₀) 的幂（例如 1 − t² 在 t₀ = 1 处是 −2(t − 1) − (t − 1)²）。这是课本做法，但式子会长一些。
12. **MCP 的两个新工具没有 widget**（只返回文字，和面板同一套措辞）。要在 Claude 里也画部分和的图，需要新的 Scene 种类和一次 widget 升级（大家都要删除连接器重加），所以本轮没做。
13. **讲课模式不影响面板**（推导本身就是要投屏的内容，只是字变大）。如果投屏时觉得太长，可以在讲课模式下只显示递推公式和拆分两步。
14. **本地预览**：worktree 里没有自己的 node_modules，Turbopack 拒绝指向工作区外的链接；这轮的浏览器实测用的是 `next dev --webpack` 加一个指向主仓库 node_modules 的目录联接（`node_modules` 被 gitignore，不进仓库）。Turbopack 的生产构建在 worktree 里跑时临时把 `turbopack.root` 指向主仓库，跑完还原（`next.config.ts` 没有改动进提交）。
15. **Frobenius「无法判断」**：两个指标根相差整数 N 时，第二个解要不要对数项要算到 n = N 才知道。N 超过 200（`FROBENIUS_GAP_CAP`），或系数的位数先到上限，就如实说「无法判断」，不展开。课本里的 N 都很小（Bessel 的 2ν），只有构造出来的题目会撞到。
16. **被证明的下界可能很弱**：数值求出的奇点现在都带一个**被证明的**包含半径（Weierstrass / Braess–Hadeler：每个根都落在某个近似值周围 n|W_i| 的圆里，W_i 用高斯整数精确算）。病态多项式（(t² + 10⁻¹⁶)((t − 10⁸)² + 3)、离展开点很远的根对）的包含半径很大，这时只能报告无根圆的下界，它可能比真实半径小。要更好，需要先把多项式精确平移到 t₀ 再求根，或者用区间算术 / Sturm 序列做精确隔离。
17. **近共振**：近似输入（x'' + 2x = cos(√2 t)，√2 以 16 位小数进入）面板拒绝并说明；精确输入（cos(1.41421356237 t)）给出精确公式，但它的各项约 10¹¹ 并且相消，浮点运算无法再和数值解比较，核对句如实说只做了精确代入。真正的修法是在 Q(√2) 里精确运算（同第 3 条）。
18. **链接解码只做静态检查**：只被画面数值拒绝的 eq（Frobenius 题目），服务器解码链接时只检查它能否被解析、x'' 是否出现、按结构是否线性，**不做精确读法**（第二轮评审发现：一个 35 到 82 个字符的链接能让服务器算 9 到 310 秒）。精确读法在页面上、在面板自己的 1.5 s 预算里做。
    **原有的代价没有改**：内核的 `reduceSecondOrder`（冻结）没有 checkpoint。一个 142 个字符的 Wilkinson 型方程 (t − 1)(t − 2)…(t − 20)x'' + x = 0 在里面要 4 到 10 秒。画面、`analyze_second_order` 和链接解码本来就要付这个代价。
    面板这边（第四轮）已经尽量绕开它：
    - 网页上直接用画面已经算过的结果；
    - 其他情况先用一个只查语法的预检（`secondOrderSyntaxPasses`），通过就不再采样；
    - 只有真要做参考积分（公式的核对、画图）时才化简。

    第五轮起，参考积分在没有画面结果时也不再调用内核化简，而是直接按学生的方程求值（E 关于 x'' 是仿射的）。所以面板和两个 MCP 工具都不会再等内核。剩下的只有画面自己的编译和 `analyze_second_order`（原有工具）：要解决，需要给 `reduceSecondOrder` 加一个 checkpoint 参数。这是静态改动，但内核冻结，需要你明确同意。
19. **面板在服务器渲染时也会算一次**：链接带 `ser` 时，页面第一次渲染（在服务器上）就会算级数或公式，上限是面板自己的 1.5 s。这和画面本身（平衡点等）在服务器上的计算是同一类代价；公开页面没有限流。如果 Vercel 的用量显示这里有问题，可以改成只在浏览器里算（需要处理首屏和水合的一致）。
20. **快模态的核对区间很窄**：核对区间是 |t − t₀| ≤ min(1, 8/|Re r|最大)，所以 y' = 40(y − t) 只在 |t| ≤ 0.2 上和数值解比较。这是为了让积分器自身的误差（按 e^(|Re r||t − t₀|) 放大）不把正确的公式判错；句子里写的就是实际比较的范围。
